# 接口清单与调用示例

所有接口统一返回：

```json
{ "code": 0, "msg": "ok", "data": { } }
```

`code=0` 表示成功。出错时 FastAPI 会返回 `{"detail": "错误原因"}`，状态码 400/401/403/404/500。

除 `/api/health`、`/api/auth/register`、`/api/auth/login` 外，其余接口都要在请求头带：

```
Authorization: Bearer <登录返回的 token>
```

---

## 1. 健康检查

`GET /api/health`

```json
{
  "code": 0,
  "msg": "ok",
  "data": { "app": "采购文档智能生成系统 v2", "database": "sqlite+aiosqlite", "ai_enabled": false }
}
```

`ai_enabled=false` 说明没配 `AI_API_KEY`，此刻走的是本地规则。

---

## 2. 注册

`POST /api/auth/register`

```json
{ "username": "zhangsan", "password": "123456", "display_name": "张三" }
```

返回 `data`：`{"username": "zhangsan", "display_name": "张三", "role": "buyer"}`

> 密码 6–32 位，用户名 3–32 位且不能重复。注册出来的账号角色固定是 buyer。

---

## 3. 登录

`POST /api/auth/login`

```json
{ "username": "admin", "password": "Jhj@123456" }
```

返回：

```json
{
  "code": 0,
  "msg": "登录成功",
  "data": {
    "token": "8f3c...（48位十六进制）",
    "user": { "username": "admin", "display_name": "管理员", "role": "admin" }
  }
}
```

密码连错 5 次会锁 10 分钟，此时返回 **403**，`detail` 里带解锁时间。

---

## 4. 查当前用户 / 退出

- `GET /api/auth/me` → 返回当前用户信息
- `POST /api/auth/logout` → 删除数据库里这条 token

## 5. 品类

```json
{
  "code": 0,
  "data": [
    {
      "id": 1,
      "code": "server",
      "name": "服务器采购",
      "keywords": ["服务器", "CPU", "内存", "硬盘", "机架", "虚拟化"],
      "contract_type": "货物采购合同",
      "contract_terms": { "payment": "...", "acceptance": "...", "dispute": "..." },
      "template_file": "",
      "template_placeholders": []
    }
  ]
}
```

### 新建 `POST /api/categories`（admin）

```json
{ "code": "network-device", "name": "网络设备采购", "keywords": ["交换机", "路由器", "防火墙"], "contract_type": "货物采购合同" }
```

### 上传模板 `POST /api/categories/{code}/template`（admin）

`form-data`，字段名 `file`，只接受 `.docx`。

接口会读模板里的 `{{字段名}}` 或 `{字段名}`，识别出占位符返回：

```json
{ "code": 0, "data": { "template_file": "server_模板.docx", "placeholders": ["项目名称", "预算金额"] } }
```

## 6. 生成采购文件（核心接口）

`POST /api/records/generate`

```json
{
  "title": "2026年机房服务器采购项目",
  "content": "采购机架式服务器100台。预算为800万元。合同签订后45天内完成供货和安装调试。CPU要求不低于32核64线程，内存不低于512GB DDR5，硬盘不低于2块960GB SSD，网络配置双万兆网卡。质保3年，需提供培训服务和远程运维支持。",

  "delivery": "",
  "supplier": "具备营业执照、具备同类项目经验、具备原厂授权",
```

## 7. 记录列表（分页 + 搜索）

`GET /api/records?page=1&size=10&keyword=服务器`

```json
{
  "code": 0,
  "data": {
    "total": 3,
    "page": 1,
    "size": 10,
    "items": [ { "id": 1, "generation_no": "...", "title": "...", "parser": "local-rule", "create_time": "..." } ]
```

## 9. 调整章节

`POST /api/records/{id}/adjust`（expert / admin）

```json
{ "section": "bid", "content": "本项目的采购背景由业务部门提出，现按流程组织采购。" }
```

`section` 只能是 `techSpec` / `announcement` / `bid` / `contract` / `evaluation`。

调整后该章节变成一段文字，并在 `versions_json` 里留一条"修改前"的记录。

---

## 9b. 块级编辑（只改其中一块）

`PATCH /api/records/{id}/document`（expert / admin）

和 `/adjust` 的区别：`/adjust` 是**整章替换**，这个接口只动第 `index` 块，同章节的其他段落、列表、表格全部保留。

```json
{
  "section": "techSpec",
  "index": 0,
  "action": "replace",
  "block": { "type": "p", "text": "这段是块级编辑改出来的内容。" }
}
```

| 字段 | 说明 |
|---|---|
| `section` | 五个章节之一 |
| `index` | 块下标，从 0 开始；`insert` 时表示插到第几个位置 |
| `action` | `replace` 替换 / `insert` 插入 / `delete` 删除 |
| `block` | 新的块；`delete` 时不用传 |

`block` 支持三种类型（和 `sections_json` 里的结构一致）：

```json
{"type": "p", "text": "一段话"}
{"type": "list", "items": ["第一条", "第二条"]}
{"type": "table", "rows": [["设备", "数量"], ["服务器", "100台"]]}
```

**会自动校验并拒绝的情况**（都返回 400）：`index` 越界、段落为空、`list` 一条都不剩、
表格每行列数不一致、列数超过 12、单章删到 0 块。

每次编辑都会往 `versions_json` 追加一条整章快照，所以可以用第 10 节的回滚接口还原。

## 10. 版本历史 / 回滚

- `GET /api/records/{id}/versions` → 返回修改历史列表
- `POST /api/records/{id}/versions/{index}/restore` → 把第 `index` 条改动前的版本还原回去

```json
[
  {
    "time": "2026-11-07 20:41:37",
    "user": "admin",
    "section": "bid",
    "before": { "title": "招标文件主体", "blocks": [ ... ] }
  }
]
```

---

## 11. 重新生成 / 重新预审

- `POST /api/records/{id}/regenerate` → 按原需求再生成一条新记录，`parent_id` 指向老记录
- `POST /api/records/{id}/review-risks` → 重新跑一遍风险规则（配了 Key 还会加一轮模型复核）

## 12. 下载 Word

`GET /api/records/{id}/download`

返回 `application/vnd.openxmlformats-officedocument.wordprocessingml.document` 的二进制流，文件名是 `生成编号_项目名称.docx`。

浏览器里直接访问这个地址不会下载，因为需要请求头带 token；在 `/docs` 里点 "Try it out" 或者在代码里下载即可。

---

## 13. 批量导入 Excel

`POST /api/records/import-excel`（form-data，字段名 `file`）

表格要求（列名支持几种常见写法）：

| 标题（必填） | 需求正文（必填） | 预算 | 交付周期 | 供应商要求 | 品类编码 |
|---|---|---|---|---|---|
| 办公笔记本采购 | 采购笔记本电脑50台，预算为100万元…… | 1000000 | 20天 | 具备营业执照 | office-device |

返回：

```json
{ "code": 0, "msg": "批量导入完成", "data": { "count": 2 } }
```

一次最多处理 50 条；批量导入只走本地规则（不逐条调大模型），否则 50 条 × 30 秒会把接口拖死。

---

## 14. 导出记录清单

`GET /api/records/export-excel` → 返回 .xlsx，列是：生成编号、项目名称、采购品类、预算金额、采购数量、交付周期、风险条数、解析方式、创建人、创建时间。

- `GET /api/admin/audit-logs?page=1&size=20` → 审计日志分页
- `GET /api/admin/users` → 用户列表（不含密码）
- `GET /api/admin/stats` → 记录总数、用户总数、按品类分布

```json
{
```

## 16. 错误码速查

| 状态码 | 什么时候出现 | 处理办法 |
|---|---|---|
| 400 | 用户名重复、品类编码重复、章节名不对、表格缺列 | 按 detail 改参数 |
| 401 | 没带 token / token 无效 / token 过期 / 密码错 | 重新登录 |
| 403 | 角色没权限（如 buyer 查审计日志）、账号被锁定 | 换账号或等解锁 |
| 404 | 记录 id 或品类编码不存在 | 核对 id |
| 500 | 没预料到的异常（日志里有完整堆栈） | 看服务端日志 |
