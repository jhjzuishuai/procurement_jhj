# 面试化改造清单（面试官视角）

> 目标岗位：郑州 / 杭州中小厂 Python 后端（含外包、SaaS、电商、传统信息化）
> 评估对象：`procurement_jhj`（FastAPI + 异步 SQLAlchemy + httpx + Pandas + python-docx）
> 作者：贾皓杰 (JHJ)

---

## 一、先说结论

现有项目作为**「能跑、有分层、有测试、有文档」的作业级项目**，交付质量在应届生里属于中上（分层清晰、有 23 项自测、有降级设计）。

但作为**面试项目**，它有一个结构性问题：

> **它是「功能完整」的，不是「有难度」的。**

面试官不会因为你实现了 22 个接口就加分——那是体力活。他们加分的地方是：
**你在哪个点上遇到了真正的问题、怎么定位、怎么权衡、怎么证明改好了。**

按这个标准，现有项目能被追问 2 轮就到底：所有技术选择都停在「能用」，没有一处有量化、有对比、有权衡。

**给分：工程化 8/10，技术深度 3/10，可讲述性 4/10。**

- 郑州的外包/传统信息化岗（华为外包、中软、软通、宇通这类）：现状**够用**，他们要的是"能上手干活、能看懂已有代码、Linux 命令会敲"。
- 杭州的中小厂（电商、SaaS、工具类）：**不够**，这些岗位必问 Docker、CI、MySQL 索引、并发、缓存，你现在一个都答不实。

## 二、五个硬缺口（带代码定位，这是面试官会当场戳的地方）

### 缺口 1：没有技术难点，全是 CRUD + 模板拼接

| 现在的做法 | 面试官会问 | 你的问题 |
|---|---|---|
| 正则捞字段，模型填空 | 准确率多少？举一个误判的例子 | 没有样例集、没有准确率数字，答不出来 |
| `call_ai` 一次 POST | 模型超时 30 秒会怎样？失败了怎么办？ | 只有"返回 None 降级"，没有重试、没有超时分级、没有成本估算 |
| `build_sections` 拼字符串 | 换个品类要改代码吗？ | 要改代码（写死在函数里），不是配置驱动的 |

**修法（最小可讲的技术故事）**：
建一份 **20 条黄金样例**（`tests/fixtures/parse_cases.json`），每条写清"输入正文 → 期望的 budget/quantity/category/technical 条数"。写一个小脚本跑全量、输出准确率表（例如 18/20 = 90%），把误判的那 2 条修掉并记录原因。
这一个动作同时解决三件事：有了量化、有了回归测试、有了"我修了什么"的故事。

### 缺口 2：数据建模偷懒 —— JSON 列当业务表用

代码里 5 个 JSON 列承载了全部业务内容（`models.Record`）：

```
requirement_json / parameters_json / sections_json / risks_json / versions_json
```

短期省事，长期三个硬伤：

| 硬伤 | 现象 | 面试官追问 |
|---|---|---|
| **并发丢更新** | `records.adjust_record` 是"读 JSON → 改 → 写回"，两个人同时改同一章节，后写的把先写的覆盖掉 | "并发怎么处理？" |
| **无法查询/索引** | `admin.stats` 只能全表拉出来在 Python 里累加 | "10 万条记录你这接口要多久？" |
| **版本无上限** | `versions_json` 是个不断变长的数组，改 50 次就把 50 份全文塞进一行 | "这一行会多大？" |

**修法（挑一个做透，别全做）**：
- 最小改：`Record` 加一列 `version: Mapped[int]`（默认 0），`adjust` 时 `UPDATE ... WHERE id=? AND version=?`，更新成功才 `version+1`，失败返回 409。这就是**乐观锁**，一行 SQL 讲得清。
- 加分改：把 `versions_json` 拆成独立表 `record_version(id, record_id, section, content_json, created_by, create_time)`，append-only。这一步能讲"为什么反范式化要还回去"。

### 缺口 3：鉴权有三处真实可被攻击的点（最容易被追问细节）

**3.1 登录锁定可被匿名 DoS**　`app/routers/auth.py::login`

```python
if user.failed_times >= 5:
    user.locked_until = datetime.now() + timedelta(minutes=10)
```

失败次数只按 `username` 计数，不绑 IP。**任何人只要连错 5 次 `admin`，就能把管理员锁 10 分钟，循环往复可以永久锁死。** 这是真实漏洞，不是理论问题。

修法：计数键改成 `(username, ip)`；或对同一 IP 加"每分钟最多 5 次登录尝试"的限流（纯 Python 字典 + 时间窗口就够，不必上 Redis）；锁定阈值改指数退避（1 分钟 → 5 → 15）。

**3.2 上传文件名路径穿越**　`app/routers/categories.py::upload_template`

```python
save_name = code + "_" + file.filename.replace(" ", "_")
save_path = config.TEMPLATE_DIR / save_name
```

`filename` 来自客户端，完全可控。传一个 `..\..\..\evil.docx` 就能往模板目录外写文件。只替换空格挡不住任何东西。

修法：丢弃原文件名，用 `uuid4().hex + ".docx"` 存盘，原始名只写进数据库做展示。附带再做两件事：校验 zip 结构（docx 本质是 zip，能挡伪装文件）、解压前检查成员总大小（挡 zip bomb）。

**3.3 token 只增不减、明文入库**　`app/models.py::UserSession`

每个用户每次登录都新增一行，从不清理；token 明文存库，库被读走等于所有会话被劫持。

修法：token 存 `sha256(token)`，查的时候先哈希再比；加一个 `DELETE FROM user_session WHERE expire_at < now()` 的清理（放在 lifespan 启动时跑一次，或用 APScheduler）。这一步还能讲"为什么 JWT 无状态反而更难撤销"。

### 缺口 4：列表接口返回全量章节（就是你计划里那个 366KB）

`records.record_to_dict()` 返回了 `sections`（5 个章节全文），而 `list_records` 复用同一个函数，所以每页 10 条 = 10 份完整文档。

**修法**：拆两个函数——`record_summary()`（列表用，去掉 `sections`/`requirement`/`risks` 明细，只留标题、编号、品类、预算、风险条数）和 `record_to_dict()`（详情用）。顺便给列表加 `？fields=` 或固定的瘦身字段。

**验收要量化**：改前 `响应体 366KB / 10 条`，改后 `约 15KB`，并给出"前端首屏渲染时间从 x ms 到 y ms"。这就是一条能写进简历的量化战绩。

---

### 缺口 5：测试不隔离，也没有 CI

`tests/test_api.py` 直接 `create_all()` + 写真实 `data/app.db`。后果：

- 跑一次测试，开发库被塞进测试数据（你自己就删过 `data/app.db` 好几次）
- 断言是 `print("[通过]")` 的脚本，不是 pytest 的 fixture/参数化
- 没有任何自动化：改完代码靠人肉跑脚本

**修法**：
1. 用 `tmp_path` + `sqlite+aiosqlite:///{tmp}/test.db` 覆盖 `config.DATABASE_URL`，每个测试一个干净库
2. `conftest.py` 提供 `client`、`admin_token`、`buyer_token` 三个 fixture
3. 用 `@pytest.mark.parametrize` 覆盖边界（预算 0 / 800万 / 800元、size=100 压回 10、章节名非法、重复用户名、第 5 次锁定）
4. `pytest-cov` 至少 70%
5. GitHub Actions 一个 workflow：`pip install -r requirements-dev.txt && pytest`

这五步做完，"测试"才从"我写了脚本"变成"我有工程规范"。

### 缺口 6（附加）：可观测性为零

有 `logging.info`，但没有：

- **请求 ID**：出问题无法把 5 条日志串成一次请求
- **慢请求标记**：不知道哪个接口慢（只能靠感觉）
- **指标**：没有 QPS / P95 / 错误率
- **结构化日志**：现在是人读的格式，机器不好聚合

修法（2 小时够）：一个 middleware 生成 `request_id` 塞进 `contextvar`，日志格式带上它；`finally` 里算耗时，超过 500ms 打 `WARNING`；加一个 `/api/metrics` 返回"总请求数 / 错误数 / 各接口 P50 P95"（进程内字典即可，不用 Prometheus）。

## 五、面试官会问的 12 个问题（现在答不出的就是缺口）

按"你能答 / 勉强答 / 答不出"自查，答不出的先补，补不了的就从简历上删掉这项。

| # | 问题 | 期望的答法要点 | 现状 |
|---|---|---|---|

### 8.1 实习面试官实际在筛什么（和正式岗差别很大）

| 维度 | 实习真实标准 | 你的现状 |
|---|---|---|
| 项目是不是抄的 | 能不能说清每个决定、答得住"这里为什么这么写" | ✅ 强项（你逐文件讲过一遍） |
| 能不能跑起来 | 本地能跑、能演示、代码能给人看 | ✅ 已有 23 项自测 + 三份文档 |
| 有没有工程习惯 | 有 Git 提交历史、有 README、有一点测试 | ⚠️ Git 未建、测试是脚本 |
| 基础八股 | HTTP/状态码、索引、事务、异步、SQL | ⚠️ 未见准备痕迹 |
| 能不能上手干活 | 装环境、敲 Linux 命令、改小需求 | ⚠️ 未验证过实操 |
| 技术深度 | **不问**（问了也是"你知道有这回事吗"级别） | 不用补 |

关键差别：**正式岗问"你怎么解决的"，实习问"这是你自己写的吗"。** 所以实习阶段该投入的是"讲清楚 + 能跑 + 有痕迹"，不是"补技术深度"。

| D3 | 2h | 列表瘦身（366KB→15KB）+ 补一条测试 | 唯一需要的"量化战绩"，1 条足够撑简历 |
| D4 | 2h | README 重写：截图 + 一条请求的时序图 + 5 张表的关系图 + 快速启动三步 | 面试官只看这页 |
| D5 | 2h | 录 2 分钟演示视频：登录 → 生成 → 看章节 → 下载 Word | 比公网地址更稳（地址会挂，视频不会） |
| D6 | 1.5h | 本地 Dockerfile（可选）+ `docker compose up` 跑通截图 | 有就加分，没有不扣分 |
| D7 | 1h | 简历措辞定稿 + 自述稿（3 分钟讲完项目） | 实习成败一半在"讲" |

合计约 12.5h。**砍掉的**：Alembic（实习几乎不问，SQLite 场景更没必要）、前端单页（Swagger 够看）、公网部署（视频替代）、CI（GitHub Actions 有空再说）。

### 8.3 省下的 8 小时投到哪里（这是真正决定 offer 的部分）

1. **基础八股（3h）**：HTTP 方法与状态码（401/403/404/409/422）、GET/POST 区别、幂等、Cookie/Session/Token 区别、数据库索引为什么能加速、事务 ACID、SQLite 与 MySQL 差异、`async/await` 与线程的区别、GIL 是什么。
2. **手写小接口（2h）**：不看项目代码，从零写一个"带登录 + 一个 CRUD + 一个分页"的 30 行服务。实习面试经常让你现场写。
3. **Linux 实操（1.5h）**：`ls/cd/tail -f/ps/grep/netstat/df/chmod/systemctl/journalctl`，会用 `ssh` 连一次机器。郑州外包岗必问。
4. **SQL 手写（1.5h）**：`SELECT ... WHERE ... ORDER BY ... LIMIT`、`JOIN`、`GROUP BY`、`EXPLAIN` 看执行计划。面试基本都会给一张表让你写。

### 8.4 实习级 8 问（这几条能答就够，不必追第五节那 12 问）

1. 这个项目是你自己写的吗？哪部分最难？
2. 一条"生成采购文件"的请求，从进来到返回经过哪些文件？
3. 为什么要分 routers/services/models 三层？不分会怎样？
4. 密码怎么存的？为什么不存明文？
5. 用户没登录访问接口，你怎么拦的？（401 和 403 区别）
6. 数据库有几张表？分别存什么？
7. 你的测试怎么跑的？跑一次多久？
8. 如果让你加一个"删除记录"的接口，你要改哪几个文件？（答案：schema + records.py + 一条测试，不用动 service）

第 8 题是**最能证明"真写过"**的一问，因为只有真写过才知道要动哪几处。提前把答案背熟。

**技术上你不用再加强了，缺的是"痕迹"（GitHub + 提交历史 + 截图 + 视频）和"表达"（3 分钟自述 + 8 个基础问题）。**
