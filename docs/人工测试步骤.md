---

## 先说清楚：为什么没有前端

这一版只做后端，操作界面就是 FastAPI 自带的 **Swagger UI**（`/docs`）。它不是只能看文档，每个接口都有 `Try it out` 按钮，能真的填参数、发请求、看返回，效果等于一个简易前端。

要真做前端的话，旧项目的 `frontend/`（`app.js` 3958 行、`styles.css` 2709 行）可以照着接口改成纯静态页面，接口路径基本一一对应。

## 二、操作约定（先看这一节，后面省事）

**每一步都这样操作：**

1. 点开某个接口，点 `Try it out`
2. 在 `Request body` 里改 JSON，或者在参数框里填值
3. 点蓝色 `Execute`
4. 看下面 `Server response` 里的 **Code**（状态码）和 **Response body**

**带锁的接口必须先登录**：点页面右上角 `Authorize`，把 token 粘进去，点 `Authorize`。一次就够，后面所有接口自动带。

**判断通过的标准**：`Code` 是 200 且返回体里 `"code": 0`。

### 第 6 组：生成采购文件（核心功能）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 6.1 | `POST /api/records/generate`，body 见下方 | **Code = 200**，返回见下方（6 个检查点全对上才算过） |

**请求体：**

```json
{
  "title": "2026年机房服务器采购项目",
  "content": "采购机架式服务器100台。预算为800万元。合同签订后45天内完成供货和安装调试。CPU要求不低于32核64线程，内存不低于512GB DDR5，硬盘不低于2块960GB SSD，网络配置双万兆网卡。质保3年，需提供培训服务和远程运维支持。",
  "budget": 0,
  "delivery": "",
  "supplier": "具备营业执照、具备同类项目经验、具备原厂授权",
  "category_code": ""
}
```

**必须对上的 6 个点：**

| # | 检查位置 | 期望值 |
|---|---|---|
| ① | `data.parameters.budget` | `8000000`（从"预算为800万元"解析，万元 ×10000） |
| ② | `data.parameters.quantity` | `"100台"` |
| ③ | `data.parameters.delivery` | `"45天"` |
| ④ | `data.parameters.category_code` / `category_name` | `"server"` / `"服务器采购"`（关键词自动命中） |
| ⑤ | `data.sections` | 恰好 5 个键：`techSpec`、`announcement`、`bid`、`contract`、`evaluation` |
| ⑥ | `data.parameters.parser` | `"local-rule"`（没配 API Key，走本地规则） |

**另外确认：**

- `data.generation_no` 形如 `PG20261107204137123`
- `data.parameters.configuration` 里 cpu / memory / storage / network / warranty 五个都有值
- `data.parameters.technical_requirements` 是 6 条左右的技术描述，**不应该包含"预算为800万元"和"合同签订后45天"**（这两句是商务条款，已被过滤）
- `data.risks` 是 1 条 `LOW`，标题"未发现明显高风险项"（因为预算够、有交付期、资质够、技术参数够）

## 五、我实测过的结论（不是推测）

这份文档里的期望值，是我实际跑过一遍 API 才写下来的，包括：

- 模板上传返回的 7 个占位符清单（含表格内的 2 个）
- 批量导入 3 行 → `count: 3`
- `size=100` 被压回 10
- 服务器需求解析出 `8000000 / 100台 / 45天 / 服务器采购`，5 章节，风险 1 条 LOW
- 自动测试脚本 23 项全过

你自己按步骤走，结果应该一致。如果哪一步对不上，看服务端控制台的 traceback，那比 Swagger 的返回信息多。
