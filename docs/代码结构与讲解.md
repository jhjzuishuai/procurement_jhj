# 代码结构与讲解

> 这份文档回答三个问题：**分成哪几层**、**请求进来后代码怎么走**、**每个文件干什么、改了会影响谁**。
> 作者：贾皓杰 (JHJ)

---

## 一、一句话概括

这是一个「**录入一段采购需求文字 → 系统自动解析出参数 → 套模板生成 5 个章节的采购文件 → 检查风险 → 导出 Word**」的后端服务。

技术栈：FastAPI（接口）+ 异步 SQLAlchemy（存库）+ httpx（调大模型）+ Pandas（Excel）+ python-docx（Word）+ re（正则解析）。

## 三、分了几层？一层管一件事

```
                    ┌─────────────────────────────┐
   HTTP 请求  ──────►│  routers/  只做 HTTP 的事    │  取参数、判权限、调服务、返回 JSON
                    └──────────────┬──────────────┘
                                   │ 调用
                    ┌──────────────▼──────────────┐
                    │  services/  只做业务的事      │  解析、生成、导出；不 import fastapi
                    └──────────────┬──────────────┘
                                   │ 读写
                    ┌──────────────▼──────────────┐
                    │ models/ database  只做数据   │  表定义、会话、查询
                    └──────────────┬──────────────┘
                                   │
                    ┌──────────────▼──────────────┐
                    │  SQLite / MySQL              │
                    └─────────────────────────────┘

  横切的公共件：config（配置）、security（加密）、deps（登录权限）、common（返回格式）
```

四条规矩，写代码时别破坏：

1. **routers 里可以 import services，services 里绝不能 import routers**（否则循环导入，程序起不来）。
2. **services 里不出现 `Depends`、`HTTPException`**，它们收普通字典、返回普通字典，这样脱开 FastAPI 也能单独测试。
3. **models 只管表结构，不写业务方法**。
4. **一个请求一个数据库会话**：由 `Depends(get_db)` 提供，路由函数里只 `commit`，不 `close`（框架帮你关）。

## 四、请求进来之后到底发生了什么

### 链路 1：登录（最基础，先看懂这条）

`POST /api/auth/login`，body `{"username":"admin","password":"Jhj@123456"}`

| 步 | 位置 | 干什么 |
|---|---|---|
| 1 | `main.py` | 按路径 `/api/auth/login` 找到 `auth.py` 里的 `login()` |
| 2 | `schemas.LoginIn` | 校验 body 有 username、password，缺了就返回 422 |
| 3 | `database.get_db` | 开一个数据库会话，注入给 `db` 参数 |
| 4 | `auth.login` | `select(User).where(username==...)` 查人，查不到 401 |
| 5 | `auth.login` | 看 `locked_until` 是否还在锁定期，是就 403 |
| 6 | `security.check_password` | 用 PBKDF2 重新算一遍摘要，和库存的 `盐$摘要` 比 |
| 7 | `auth.login` | 密码错：`failed_times + 1`，到 5 次锁 10 分钟，然后 401 |
| 8 | `security.new_token` | 密码对：生成 48 位十六进制 token |
| 9 | `models.UserSession` | 把 `(token, username, expire_at)` 插进 `user_session` 表 |
| 10 | `common.write_audit` | 往 `audit_log` 写一条 login 记录 |
| 11 | `auth.login` | `await db.commit()` —— 一次提交，token 和日志一起落库 |
| 12 | `common.success` | 返回 `{"code":0,"msg":"登录成功","data":{"token":...,"user":{...}}}` |

**关键点**：token 存在数据库里，不是存在内存里。所以服务重启后，之前登录的人不掉线。

### 链路 2：后面每个请求都要先过"门卫"

任何需要登录的接口（比如 `GET /api/records`），参数里都写着 `user: User = Depends(current_user)`。

`deps.current_user` 做的事：

```
请求头 Authorization: Bearer eyJ...（其实是 48 位 hex，不是 JWT）
   │
   ├─ HTTPBearer(auto_error=False) 取出 token，没带就 401
   ├─ 查 user_session 表：有这条 token 吗？过期了吗？
   ├─ 查 sys_user 表：这个人还在吗？
   └─ 返回 User 对象，交给路由函数
```

然后路由里再调一句 `check_permission(user, "generate")`，查 `ROLE_PERMISSIONS` 这张表，不满足就 403。

角色 → 能做的事（`deps.py`）：

| 角色 | 权限 |
|---|---|
| admin | generate、review、records、templates、admin |
| buyer | generate、records |
| expert | generate、review、records |

所以：**buyer 改不了章节（需要 review）、admin 能看审计日志（需要 admin）、buyer 不能传模板（需要 templates）**。这三条正是自测里 401/403 用例验证的东西。

### 链路 3：生成文件（核心链路，串起了三个 service）

`POST /api/records/generate`，body 就是 `RequirementIn`：

```json
{"title":"机房服务器采购","content":"预算为800万元，采购服务器100台，合同签订后45天交付……キュメント","budget":0}
```

`records.generate_record()` 里按顺序调了 5 步：

```
① parse_requirement(requirement, categories)        ← services/parse_service.py
      │  rule_parse()            纯正则先捞：预算、数量、交付期、CPU/内存/硬盘/质保、技术要求句子
      │  call_ai()               有 key 就调模型补漏（没 key 返回 None，直接跳过）
      │  fill_empty()            只填正则没捞到的空字段（正则优先，模型补充）
      └─ 输出 parameters 字典，带 parser 字段标明本次是 "local-rule" 还是 "ai"

② build_sections(parameters)                        ← services/document_service.py
      └─ 输出 sections 字典，5 个键 techSpec / announcement / bid / contract / evaluation

③ check_risks(requirement, parameters)              ← services/parse_service.py
      └─ 6 条本地规则，输出风险列表

④ ai_review_risks(parameters)                       ← services/parse_service.py
      └─ 有 key 时让模型再挑毛病，结果追加到风险列表（type=AI_REVIEW）

⑤ Record(...) + write_audit + commit                ← models.py / common.py
      └─ 一条记录落库：需求原文、参数、章节、风险全存 JSON 列
```

返回值是 `record_to_dict(record)`，所以你打开 Swagger 点 Try it out 能看到完整的 `parameters`、`sections`、`risks`。

### 链路 4：导出 Word

`GET /api/records/{id}/download`

```
读 Record 行 → 取出 sections_json → build_docx_bytes(title, sections) → StreamingResponse 吐出 38KB 的 .docx
```

注意：Word **不是启动时生成好存磁盘的**，而是每次点下载现拼一遍。好处是"数据改了 Word 自动跟着改"，不会出现文件和数据不一致。

### 链路 5：批量导入

`POST /api/records/import-excel`，上传 xlsx

```
read_requirements(bytes)      ← Pandas 读表 → 列名别名匹配 → 转成需求字典列表（上限 50）
    │
    └─ for 每条需求: rule_parse → build_sections → check_risks → db.add(Record)
         （刻意只走本地规则，50 条 × 调一次大模型 30 秒，接口会卡死）
    │
    └─ 一次 commit，返回 {"count": 3}
```

## 五、数据在库里长什么样

5 张表，**刻意不写外键、不写 ORM relationship**，靠 `username` / `token` 字面值关联——字段少、查询简单时这样写最省事，也不会踩懒加载的坑。

| 表 | 主键 | 主要字段 | 谁在写 |
|---|---|---|---|
| `sys_user` | id | username、display_name、role、password_hash、failed_times、locked_until | auth.py、database.init_demo_data |
| `user_session` | token | username、expire_at | auth.py |
| `purchase_category` | id | code、name、keywords_json、contract_type、contract_terms_json、template_file、template_placeholders_json | categories.py、init_demo_data |
| `procurement_record` | id | generation_no、title、requirement_json、parameters_json、sections_json、risks_json、versions_json、parser、created_by、parent_id | records.py |
| `audit_log` | id | username、action、detail、ip | common.write_audit（被各路由调用） |

### 三个 JSON 列的结构（重点，理解了这个就理解项目了）

**parameters_json** —— 解析出来的标准参数：

```json
{
  "title": "机房服务器采购",
  "budget": 8000000,
  "quantity": "100台",
  "delivery": "45天",
  "category_code": "server",
  "category_name": "服务器采购",
  "contract_type": "货物采购合同",
  "contract_terms": {"payment": "...", "acceptance": "...", "dispute": "..."},
  "configuration": {"cpu": "CPU≥2.6GHz...", "memory": "", "storage": "", "network": "", "warranty": ""},
  "technical_requirements": ["...", "..."],
  "service_requirements": ["..."],
  "qualification_requirements": ["具备合法营业执照", "..."],
  "evaluation_method": "综合评分法",
  "parser": "local-rule"
}
```

**sections_json** —— 5 个章节，每个章节是"标题 + blocks 列表"，blocks 只有三种类型：

```json
{
  "techSpec": {
    "title": "技术规格书",
    "blocks": [
      {"type": "p",     "text": "一、项目概况"},
      {"type": "list",  "items": ["条目1", "条目2"]},
      {"type": "table", "head": ["参数项","要求"], "rows": [["处理器","...:"]]}
    ]
  },
  "announcement": {...}, "bid": {...}, "contract": {...}, "evaluation": {...}
}
```

这个"三型 block"的设计是关键：**文档内容先变成纯数据，再由 `build_docx_bytes` 统一渲染**。所以第 2 版想换成导出 PDF、导出 HTML，只要换渲染函数，生成逻辑一行不用动。

**risks_json / versions_json** —— 数组：

```json
// risks
[{"type":"RULE_CHECK","level":"HIGH","title":"缺少预算金额","description":"...","suggestion":"...","section":"预算参数"}]
// versions（每次调整章节前，把旧内容快照下来）
[{"time":"2026-11-08 10:30:15","user":"admin","section":"bid","before":{"title":"招标文件主体","blocks":[...]}}]
```

## 六、逐个文件详解

### 1. `app/config.py`（配置中心）

所有"可调但不想写死在代码里"的东西都在这。

| 名称 | 作用 |
|---|---|
| `BASE_DIR` | 项目根（`config.py` 往上两级），后面所有路径都基于它，所以**从哪个目录启动都不影响找文件** |
| `load_dotenv(BASE_DIR/".env")` | 读 .env；文件不存在也不报错 |
| `get_database_url()` | `.env` 里 `DATABASE_URL=sqlite` → 拼 `sqlite+aiosqlite:///D:/.../data/app.db`（用 `as_posix()` 把反斜杠转成 `/`，Windows 必须这样）；写完整连接串 → 原样当 MySQL 用 |
| `ensure_dirs()` | 建 `data/`、`data/templates`、`data/exports`，第一次运行不会因为目录不存在崩掉 |
| `AI_*` | 大模型地址、key、模型名、超时 |
| `MAX_UPLOAD_MB` | 上传模板的大小上限，默认 20 |

改它会影响：整个项目的路径和数据库指向。**换 MySQL 只改 `.env`，不动代码**。

### 2. `app/database.py`（连接与会话）

| 函数 | 说明 |
|---|---|
| `engine` | 异步引擎。SQLite 直接建；MySQL 才加 `pool_size/max_overflow/pool_pre_ping`（SQLite 不支持这些参数，混着写会报错，所以这里用 if 分开） |
| `SessionLocal` | 会话工厂，`expire_on_commit=False` 让 commit 之后还能读对象属性（不然会触发额外查询甚至报 detached） |
| `get_db()` | FastAPI 依赖，`async with` 里 `yield`，请求结束自动关闭会话 |
| `create_all()` | `Base.metadata.create_all`，只建**不存在**的表 |
| `init_demo_data()` | 先数一下有没有数据，空的才写 3 个演示账号 + 3 个采购品类。所以重启不会重复插 |

**坑（务必记住）**：`create_all` **只建表、不改表**。你给 `models.py` 加了新字段，重启服务表结构还是老的，会报"列不存在"或字段读不出来。开发阶段最简单的处理是删掉 `data/app.db` 再启动；正式一点要上 Alembic 迁移。

### 3. `app/models.py`（表定义）

`Base(DeclarativeBase)` 是所有表的父类。用 `Mapped[类型] + mapped_column(...)` 的写法（SQLAlchemy 2.0 风格）。

三个提醒：

- `insert_default=func.now()` 是"**插入时**填当前时间"；`onupdate=func.now()` 是"**更新时**自动刷新"。这两个和 `default` **不能同时写**（会报 `ArgumentError: 'default' and 'insert_default' are mutually exclusive`）——你之前踩过这个坑。
- JSON 列：`keywords_json: Mapped[list] = mapped_column(JSON, default=list)`。库里存的是 JSON 文本，Python 侧读写自动转换。
- `default=list` 不能写成 `default=[]`（可变对象共享，会串数据）。

### 4. `app/schemas.py`（入参校验）

四个模型，只校验"进来的 JSON 长什么样"：

| 模型 | 字段 | 用在哪 |
|---|---|---|
| `RegisterIn` | username(3–32)、password(6–32)、display_name | 注册 |
| `LoginIn` | username、password | 登录 |
| `RequirementIn` | title、content、budget、delivery、supplier、category_code | 生成 |
| `AdjustIn` | section、content | 调整章节 |

注意：`categories.py` 里的 `CategoryIn` 是**就地定义**的，没放这个文件里。功能没问题，但风格上不一致，以后可以搬过来统一管理。

### 5. `app/security.py`（密码与 token）

只用标准库，没有 pyjwt、没有 passlib。

| 函数 | 说明 |
|---|---|
| `hash_password(pw)` | 随机 8 字节盐 → `pbkdf2_hmac(sha256, pw, salt, 100000)` → 返回 `"盐$摘要"`。**同一个密码两次结果不同**，因为盐每次随机 |
| `check_password(pw, saved)` | 拆出盐，重算摘要，`compare_digest` 比较（防时序攻击） |
| `new_token()` | `secrets.token_hex(24)` → 48 位十六进制 |
| `token_expire_time()` | 当前时间 + `TOKEN_EXPIRE_MINUTES`（默认 720 分钟 = 12 小时） |

它不是 JWT，就是"随机串 + 库里查表"。优点是简单、能主动踢人（删库里那行就下线）；缺点是多一次查询，且分布式部署要共享库（JWT 无状态的优势）。demo 用前者合适。

### 6. `app/deps.py`（门卫）

| 名称 | 说明 |
|---|---|
| `bearer_scheme` | `HTTPBearer(auto_error=False)`。**这一句决定了 Swagger 右上角有 Authorize 按钮**，也决定了没带 token 时我们能自己返回中文提示而不是英文默认 |
| `ROLE_PERMISSIONS` | 角色 → 权限字符串列表的映射表。改权限就改这张表，不用动接口 |
| `current_user()` | 依赖：取 token → 查 `user_session` → 判过期 → 查 `sys_user` → 返回 `User`，任一步失败抛 401 |
| `check_permission(user, "xxx")` | 不在允许列表就抛 403 |

### 7. `app/common.py`（小工具）

| 函数 | 说明 |
|---|---|
| `success(data, msg)` | 所有接口统一 `{code:0, msg, data}`。前端只需要判一个 `code` |
| `now_text()` | 时间字符串，给版本快照用 |
| `new_generation_no()` | `PG + 年月日时分秒 + 3 位随机`，例如 `PG20261108103015001` |
| `write_audit(db, ...)` | 只 `db.add()`，**不 commit**。交给调用方跟业务数据一起提交，保证"要么都成功要么都不写" |

这个"不 commit"是刻意的：审计日志和业务数据在同一个事务里，业务回滚了日志也不会留下假记录。

### 8. `app/main.py`（组装）

四件事：

1. `lifespan`：启动时 `create_all` → `init_demo_data`，关闭时 `engine.dispose()`（用 `@asynccontextmanager`，不是已被弃用的 `@app.on_event`）
2. 建 `app = FastAPI(...)`，带标题、描述（就是 `/docs` 顶上那段话）、版本号
3. `add_middleware(CORSMiddleware)` 放开跨域，方便以后接前端
4. `include_router` 四次，把 4 个路由文件挂上来；再加一个免登录的 `/api/health` 和一个全局异常兜底

**全局兜底** `handle_all_error`：任何没被捕获的异常都返回 `{"code":500,"msg":"服务器内部错误：...","data":null}`，而不是把 Python 堆栈裸露给调用方（堆栈只写进日志）。

### 9. `app/services/ai_service.py`（调模型）

| 函数 | 说明 |
|---|---|
| `call_ai(system, user)` | key 为空 → 立刻 `return None`（这就是"离线也能跑"的开关）；否则 POST 到 `{AI_BASE_URL}/chat/completions`，`temperature=0.1`（抽取任务要稳），`httpx.AsyncClient` 带超时；非 200、网络异常、任何异常一律 `return None` |
| `read_json(text)` | 模型爱输出 ` ```json ... ``` `，先剥围栏，再取第一个 `{` 到最后一个 `}`，`json.loads`；不是 dict 也返回 None |

**为什么所有失败都返回 None**：这个函数的调用方都写了"拿不到就退回本地规则"，所以模型挂了、没网、key 过期，接口照样成功，只是 `parser` 字段变成 `local-rule`。这是"降级不报错"的思路。

### 10. `app/services/parse_service.py`（解析 + 风险，最大的文件）

**解析部分**（正则 → 模型 → 合并）：

| 函数 | 作用 |
|---|---|
| `split_sentences(text)` | 按中文标点切句（`。；，、` 和换行都当分隔符） |
| `first_match(text, patterns)` | 按顺序试多个正则，返回第一个命中的整段文字 |
| `find_budget(text)` | 匹配 `预算...800万/800万元/800元`，万元自动 ×10000 换成元 |
| `find_quantity(text)` | 匹配 `100台 / 20套 / 5批` |
| `find_delivery(text)` | 匹配 `45天 / 30个工作日 / 2个月` |
| `guess_category(cats, text, code)` | 用户指定了 code 就直接用；否则按"关键词命中几回"打分取最高；都没命中就拿第一个 |
| `rule_parse(req, cats)` | **纯正则的完整解析**，输出上面那份 15 个字段的 parameters。技术要求那里做了过滤：少于 6 个字的、含 `预算/合同签订/万元` 的句子不算技术要求（那是商务条款），最多留 8 条，一条没有就给一句兜底 |
| `fill_empty(base, extra)` | 模型结果只用来**填空**：正则已经捞到的一律不动。这条规则保证"模型再离谱也污染不了主体数据" |
| `parse_requirement(req, cats)` | 对外唯一入口：`rule_parse` 打底 → `call_ai` → `read_json` → `fill_empty`，最后标 `parser` |

**风险部分**：

| 函数 | 作用 |
|---|---|
| `check_risks(req, params)` | 6 条规则：无预算(HIGH)、预算÷数量单价<3000(MEDIUM)、无交付期(MEDIUM)、资质<2 条(MEDIUM)、技术要求<2 条(MEDIUM)、正文<30 字(LOW)；一条都没有时给个 LOW 的"未发现明显高风险项" |
| `ai_review_risks(params)` | 有 key 时让模型以 JSON 数组返回风险，`type` 统一标 `AI_REVIEW` 以便和规则结果区分 |

改解析规则就改这个文件；它不碰数据库、不碰 HTTP，所以可以单独拿字典喂进去测。

### 11. `app/services/document_service.py`（拼章节 + 出 Word）

| 函数 | 作用 |
|---|---|
| `money_text(n)` | 千分位：`8000000` → `8,000,000` |
| `build_sections(params)` | 生成 5 个章节的数据结构（`techSpec` / `announcement` / `bid` / `contract` / `evaluation`），每章若干 `p`/`list`/`table` 块 |
| `set_run_font(run, size, bold)` | 设宋体 + 字号；**`qn("w:eastAsia")` 那句是必须的**，只设 `font.name` 中文在 Word 里会回退成别人的字体 |
| `build_docx_bytes(title, sections)` | 遍历章节和块，`add_paragraph` / `add_table`，存进 `BytesIO` 返回 bytes。页边距 2.5cm，大标题 18pt 居中，章节标题 14pt |

**要改文档长相**（比如加页码、加公司抬头、换表格样式）→ 只改 `build_docx_bytes`；**要改文档内容措辞** → 改 `build_sections`。两者分开，互不影响。

### 12. `app/services/excel_service.py`（Pandas 两件事）

| 函数 | 作用 |
|---|---|
| `COLUMN_ALIAS` | 列名别名表：`标题/项目名称/需求标题` 都算标题列 |
| `pick_column(df, names)` | 在表里找第一个存在的列名 |
| `read_requirements(bytes)` | `pd.read_excel(BytesIO(...), dtype=str)` 全按字符串读（避免预算被读成 800.0 或科学计数），`fillna("")`；必须有标题和正文两列否则报错；预算去掉逗号和"元"再 `float`；**上限 50 条** |
| `records_to_excel(rows)` | 拼 10 列 → `df.to_excel(engine="openpyxl")` → bytes；没数据显示"暂无记录"一行 |

### 13. `app/routers/auth.py`（4 个接口）

`prefix="/api/auth"`，`tags=["登录"]`（就是 Swagger 里的分组名）。

`register` 重名 400 → `login` 见链路 1 → `me` 直接把 `current_user` 的结果转字典 → `logout` 用 `bearer_scheme` 拿到 token，`delete` 掉 `user_session` 那行。

### 14. `app/routers/categories.py`（品类与模板）

| 接口 | 关键点 |
|---|---|
| `GET /api/categories` | 读全部品类，返回结构含 `template_placeholders` |
| `POST /api/categories` | 需要 `templates` 权限（只有 admin）；`code` 重复 400 |
| `POST /api/categories/{code}/template` | 只收 `.docx`、限 20MB、存到 `data/templates/{code}_{原文件名}`、顺手解析占位符入库 |
| `DELETE /api/categories/{code}/template` | 清空 `template_file` 和占位符列 |

`read_placeholders(content)`：把**段落文字 + 所有表格单元格文字**拼起来，用 `\{\{([^}]+)\}\}|\{([^{}]+)\}` 同时匹配 `{{项目名称}}` 和 `{项目名称}` 两种写法，去重后返回。这就是"上传模板返回 7 个占位符"的实现——注意它把表格里的 2 个也算进去了，因为表格单元格单独遍历了。

### 15. `app/routers/records.py`（10 个接口，最核心）

| 接口 | 权限 | 说明 |
|---|---|---|
| `POST /generate` | generate | 链路 3 |
| `GET ""` | records | 分页 + `keyword` 模糊搜标题；`size` 上限 50，超了压回 10 |
| `POST /import-excel` | generate | 链路 5，只走本地规则 |
| `GET /export-excel` | records | 取最近 500 条 → Pandas → `StreamingResponse` |
| `GET /{id}` | records | 详情，返回全部 JSON 列 |
| `POST /{id}/adjust` | **review** | 改一个章节：先快照旧内容进 `versions`，再替换该章节 |
| `POST /{id}/regenerate` | generate | 按原需求再生成一条新记录，`parent_id` 指向老的 |
| `POST /{id}/review-risks` | **review** | 重跑 6 条规则 + 模型复核 |
| `GET /{id}/download` | records | 链路 4 |
| `GET /{id}/versions` | records | 看修改历史 |
| `POST /{id}/versions/{index}/restore` | **review** | 回滚某次修改 |

两个容易记的工程细节：

- **调整章节时必须整体重新赋值**：`record.sections_json = sections`。JSON 列如果只做 `sections["bid"] = ...` 这种原地修改，SQLAlchemy 认为字段没变，不会写库（这就是"改了没生效"的经典原因）。
- **下载用 `filename*=UTF-8''` + `quote()`**：中文文件名直接塞 header 会乱码或报错。

### 16. `app/routers/admin.py`（3 个接口，全要 admin 权限）

`audit-logs` 分页（`size` 上限 100）、`users` 列表、`stats`：记录数、用户数、按品类计数（遍历 `parameters_json` 里的 `category_name` 手工累加，因为品类名存在 JSON 里，没法直接 SQL 分组）。

### 17. `run_server.py`（入口）

```python
uvicorn.run("app.main:app", host=..., port=..., reload=True)
```

必须传**字符串** `"app.main:app"`，不能传 `app` 对象——`reload=True` 时 uvicorn 要在子进程里自己重新 import 模块。传对象的话热重载会失效或直接报错。

### 18. `tests/test_api.py`（自测）

不装 pytest，直接 `python tests/test_api.py` 跑。

- 开头 `sys.path.insert(0, ROOT)`：把项目根加进搜索路径，这样从 `tests/` 目录也能 `import app`
- 用 `httpx.ASGITransport(app=app)` 直接在进程内调接口，**不用先起服务、不占端口**
- 23 项按真实使用顺序走：健康检查 → 登录 → 生成 → 列表 → 详情 → 下载 → 调整 → 版本 → 回滚 → 预审 → 导出 → 导入 → 品类 → 审计 → 未登录 401 → 越权 403
- 末行打印 `结果：通过 23 项，失败 0 项`

## 八、三条设计主线（面试被问"为什么这么写"时可以答这三句）

1. **半结构化数据全用 JSON 列存**。
   采购文件天生是"字段固定但内容不固定"的：这版 5 个章节，下版可能 7 个章节、可能加评分表。用 JSON 列 + Python 字典，加字段不用改表结构；代价是不能用 SQL 直接按章节内容查，只能像 `admin.stats` 那样取出来在 Python 里算。数据量小的时候这笔账很划算。

2. **正则优先、大模型补充、失败降级**。
   `rule_parse` 一定先跑，保证断网也有结果；模型只用 `fill_empty` 填空，不覆盖已解析的值。这样"模型胡说"和"模型不可用"都不会让接口失败——只影响 `parser` 字段和文档精细度。

3. **内容与渲染分离**。
   `build_sections` 产出纯数据，`build_docx_bytes` 负责渲染。想换 PDF/HTML 导出，或者想给 Word 加公司模板，只改渲染层。

## 十、按链路读代码的建议顺序

别按目录顺序从头读，按"一条请求怎么走"读最快：

1. `run_server.py`（2 分钟，看它怎么起 uvicorn）
2. `main.py`（看 lifespan 和 include_router，知道总共有哪几组接口）
3. `schemas.py`（知道每个接口收什么）
4. `deps.py`（知道怎么判登录和权限）
5. `auth.py` + `security.py`（跑通"登录 → 发 token"）
6. `records.py` 的 `generate_record`（核心链路的主干，其他接口都是它的变体）
7. `parse_service.rule_parse`（最像"算法"的一段，正则怎么捞数据）
8. `document_service.build_sections` + `build_docx_bytes`（数据怎么变 Word）
9. `models.py` + `database.py`（回头看数据落在哪张表哪个列）
10. `excel_service.py` + `admin.py`（补充功能，最后看）

按这个顺序，每一步都能看到"上一步的产物被下一步吃掉"，不会读到一半卡住。
