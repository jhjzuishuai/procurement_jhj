# 新旧功能对照（Node 原版 vs FastAPI 复刻版）

> 左：`Project_7_5\Project_1`（Node + Express，`backend/server.js` 2389 行）
> 右：`procurement_jhj`（FastAPI + 异步 SQLAlchemy，18 个源码文件）
> 接口数**不是靠记忆数的**，是两边 grep 路由定义得到的：原版 29 个路由，新版 22 个 router + `main.py` 的 health = 23 个。

---

## 一、总览

| 维度 | 原 Node 版 | 现在的 FastAPI 版 | 谁更好 |
|---|---|---|---|
| 框架 | Express 4，全同步回调 | FastAPI + 异步（`async/await`） | 新版（有自动文档） |
| 数据存储 | **单个 `db.json`**，`loadDb()` 读全文、`saveDb()` 写全文 | **5 张真表**（SQLite / 一行切 MySQL） | 新版（原版每次请求都读写整个文件） |
| 表/集合 | users / sessions / categories / records / auditLogs 全在一个 JSON 里 | `sys_user` / `user_session` / `purchase_category` / `procurement_record` / `audit_log` | 新版 |
| 密码 | 裸 `sha256(password)`（无盐） | PBKDF2-HMAC，10 万次迭代 + 随机盐（`盐$摘要`） | 新版 |
| 会话 | `createSessionForUser` 写进 db.json | `user_session` 表 + `expire_at` 字段 | 新版（有过期时间） |
| 登录防护 | 验证码 + 5 次错锁 **15 分钟**（返回 423 + 剩余次数） | 5 次错锁 **10 分钟**（返回 403），**无验证码** | 原版稍强（有验证码，且提示剩余次数） |
| 解析逻辑 | 散在 server.js 里、**同一套规则复制了 4 处** | 单独 `parse_service.py`，**只有一份** | 新版（这是最大的重构收益） |
| 大模型 | 调 API，key 必需 | 调 API，**key 为空自动降级为纯本地规则** | 新版 |
| 文档生成 | 服务端拼 docx | `document_service.py`，宋体 + 5 章节 | 相当 |
| 接口文档 | 无（要手写） | `/docs` 自动生成 + Authorize 按钮 | 新版 |
| 测试 | 无自动化脚本 | `tests/test_api.py` 23 项断言 | 新版 |
| 分页 | `GET /api/records` 返回**全部记录** | 分页 + `keyword` + `size` 上限 50 | 新版 |
| 批量处理 | 无 | 批量导入 Excel、批量导出 Excel | 新版 |

**一句话**：功能覆盖约为原版 **70%**，但工程质量（分层、安全、可测、可迁移）明显更高。

## 二、逐接口对照（29 vs 23）

### 2.1 两边都有（功能对齐）

| 功能 | 原 Node | 新 FastAPI | 差异说明 |
|---|---|---|---|
| 健康检查 | `GET /api/health` | `GET /api/health` | 一致 |
| 注册 | `POST /api/register` | `POST /api/auth/register` | 新版多了 `/auth` 前缀 |
| 登录 | `POST /api/login`（**要验证码**） | `POST /api/auth/login`（不要验证码） | 新版简化了 |
| 查当前用户 | `GET /api/me` | `GET /api/auth/me` | 新版返回字段少（username/display_name/role） |
| 生成采购文件 | `POST /api/generate` | `POST /api/records/generate` | 新版归到 records 下 |
| 记录列表 | `GET /api/records`（**全量**） | `GET /api/records`（**分页**） | 新版支持 page/size/keyword |
| 重新生成 | `POST /api/records/:id/regenerate` | `POST /api/records/{id}/regenerate` | 新版生成新记录并带 `parent_id` |
| 调整章节 | `POST /api/records/:id/adjust` | `POST /api/records/{id}/adjust` | 新版只支持**整章替换**（原版支持块级） |
| 风险预审 | `POST /api/records/:id/review-risks` | `POST /api/records/{id}/review-risks` | 新版 6 条规则 + 可选 AI 意见 |
| 版本历史 | `GET /api/records/:id/versions` | `GET /api/records/{id}/versions` | 新版返回数组下标（原版是 versionId） |
| 回滚 | `POST .../versions/:versionId/restore` | `POST .../versions/{index}/restore` | 新版用**下标**，原版用 id |
| 下载 Word | `GET /api/records/:id/download` | `GET /api/records/{id}/download` | 新版每次都现场生成 |
| 品类列表 | `GET /api/categories` | `GET /api/categories` | 新版字段名转成 `keywords` 等 |
| 新建品类 | `POST /api/categories`（multipart，带模板） | `POST /api/categories`（JSON）+ 单独上传模板 | 新版拆成两步 |
| 上传模板 | 含在上面 | `POST /api/categories/{code}/template` | 新版返回解析出的占位符 |
| 删模板 | `DELETE /api/categories/:id/template` | `DELETE /api/categories/{code}/template` | 新版用 code 而不是 id |
| 用户列表 | `GET /api/admin/users` | `GET /api/admin/users` | 原版带角色/权限字典，新版只列用户 |
| 审计日志 | `GET /api/admin/audit-logs` | `GET /api/admin/audit-logs` | 新版分页 |
| 审计导出 | `GET /api/admin/audit-logs/export` | **无** | 见 2.3 |
| 清理日志 | `DELETE /api/admin/audit-logs` | **无** | 见 2.3 |

### 2.2 新版新增（原版没有）

| 新接口 | 作用 | 价值 |
|---|---|---|
| `POST /api/auth/logout` | 显式退出，删掉当前 token | 原版只能等过期 |
| `GET /api/records/{id}` | 记录详情 | 原版前端从列表里自己捞 |
| `POST /api/records/import-excel` | 上传 Excel 批量生成 | **原版没有的实用功能** |
| `GET /api/records/export-excel` | 记录清单导出 Excel | 同上 |
| `GET /api/admin/stats` | 记录数/用户数/品类分布 | 原版的 usage 接口的简化版 |

### 2.3 原版有、新版没有（12 个）

| 原版接口 | 作用 | 为什么没做 | 补回成本 |
|---|---|---|---|
| `GET /api/captcha` + 登录校验 | 图形验证码 | 后端要生成图片、存临时答案，超出"基础函数"约束 | 2h |
| `POST /api/recommendations` | 需求智能推荐（补全字段） | 依赖模型，离线没法演示 | 1.5h |
| `POST /api/records/:id/optimize-terms` | 条款优化（改写合同措辞） | 同上 | 1.5h |
| `PATCH /api/records/:id/document` | **按块编辑**（p/list/table 里的某一条） | 新版只做整章替换，块级编辑要处理下标、越界、重建 blocks | 2h |
| `POST /api/records/:id/signature` | 电子签章 | 要处理图片盖章、定位 | 3h |
| `GET /api/records/:id/collaboration` | SSE 多人协同 | 要处理长连接、广播、冲突 | 6h+ |
| `GET /api/records/:id/preview.docx` | Word 在线预览 | 前端靠 `docx-preview` 渲染，是前端能力不是后端 | 0.5h（后端） |
| `GET /api/admin/usage` | 使用概览 / 看板数据 | 新版 `stats` 是它的简化版 | 1h |
| `GET /api/admin/audit-logs/export` | 审计日志导出 CSV | 用 `export-excel` 的思路可以补 | 0.5h |
| `DELETE /api/admin/audit-logs` | 清理旧日志 | 数据维护功能，演示不需要 | 0.5h |
| `PATCH /api/admin/users/:username` | 改用户角色 / 启用禁用 | 新版只能靠改库 | 1h |
| `DELETE /api/categories/:id` | 删除整个品类 | 新版只删模板 | 0.5h |

**合计约 21 小时**——这也是为什么面试化改造里建议**不补这些**：它们是"功能完整度"，不是"技术深度"。

### 2.4 同功能但实现不同（面试会被问的）

| 点 | 原版 | 新版 | 该怎么说 |
|---|---|---|---|
| 存数据 | `saveDb()` 把整个库写回 `db.json`（每次写都要序列化全部记录） | 每张表独立行，`commit` 只写变更 | "原版是文件数据库思路，并发写会互相覆盖；新版交给 SQL 事务" |
| 密码 | 裸 `sha256`，同密码永远同摘要，可彩虹表反查 | PBKDF2 + 随机盐 + 10 万次迭代 | "加盐让相同密码产生不同摘要，迭代抬高暴力破解成本" |
| 解析 | 4 处重复的规则，改一处要改四遍 | 一份 `parse_service` | **这是最重要的重构收益，面试必讲** |
| 令牌 | 无过期字段 | `expire_at` | "会话可过期、可主动撤销" |
| 列表 | 全量返回 | 分页 + size 上限 | "防止一次拉 366KB 打满内存" |
| 锁定 | 15 分钟，返回剩余次数 | 10 分钟，不返回剩余次数 | 新版更保守（不泄露还剩几次） |

## 三、现在的后端到底"包含什么"（简历/面试口径）

**代码**：18 个源码文件，4 层（routers 4 / services 3 / models + database / config 等基础设施）

**接口**：23 个（认证 4、品类 4、记录 11、管理 3、健康检查 1）

**数据**：5 张表、3 个 JSON 列（参数 / 章节 / 版本）

**业务链路**：
```
登录（失败锁定）→ 录入需求 → 正则解析 15 个参数（模型补空）
→ 品类匹配 → 生成 5 章节 → 6 类风险预审 → 导出 Word
        ↑ 另有：版本历史 / 回滚 / Excel 批量导入 / Excel 导出 / 审计日志 / 角色权限
```

**能演示的**：Swagger 全流程、23 项自测全过、Word 结构（5 章 44 段 4 表）、模板占位符识别（7 个）、`size=100` 被压回 10。

## 四、面试话术（重要）

**不要说**："我实现了原项目的全部功能。" —— 面试官一对照就发现少了 12 个接口。

**要说**：

> "这是我基于一个已有 Node 系统做的**重构**，不是从零做的。我保留了核心链路（登录、生成、解析、风险、导出、版本），
> 砍掉了签章、协同、推荐这些依赖外部服务的边缘功能，把精力放在**架构和工程质量**上：
> 把原来复制 4 份的解析逻辑收敛成一份、把单文件 JSON 库拆成 5 张表、把明文 sha256 换成 PBKDF2 加盐、
> 补了分页和批量导入导出。功能覆盖约 70%，但可维护性和安全性比原版好。"

这段话有三个好处：**诚实**（承认是重构）、**有取舍**（说明砍了什么、为什么）、**有量化**（70%、4 份→1 份、5 张表）。
比"我做了 23 个接口"强得多。
